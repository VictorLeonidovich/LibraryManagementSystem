Веб-приложение для управления библиотечной системой, построенное на базе Java-фреймворка Spring Boot.

## 🛠 Технологический стек

* **Backend:** Java, Spring Boot 4, Spring Data JPA (Hibernate)
* **Frontend:** HTML5, Thymeleaf
* **Сборка и зависимости:** Maven, MapStruct
* **Базы данных и миграции:** Liquibase
* **Мониторинг и валидация:** Spring Boot Actuator, Jakarta Validation

---

## 🏛 Архитектура проекта

Приложение реализует классическую монолитную архитектуру:
* **UI-слой:** Серверный рендеринг (SSR) веб-страниц с помощью Thymeleaf.
* **API-слой:** Выделенный REST API с DTO-маппингом (MapStruct) и собственным обработчиком исключений.
* **Бизнес-логика:** Сервисный слой на Java для обработки правил библиотеки.
* **Данные:** Модель данных (JPA-сущности) для книг, авторов, категорий и издателей.

## 📊 Мониторинг, метрики и логирование (Observability)

В проект встроена полноценная production-ready система мониторинга на базе **Spring Boot Actuator**, **Micrometer**, **Prometheus** и **Grafana** для отслеживания производительности JVM, потребления памяти и пропускной способности HTTP-запросов в реальном времени.

Базовая точка входа для проверки метрик приложения:
👉 **http://localhost:8080/actuator**

Поведение системы и доступ к метрикам настроены в зависимости от активного профиля:

### 🛠️ В профиле разработки (dev):
Доступны **все** встроенные эндпоинты управления (`management.endpoints.web.exposure.include=*`).
* **`/actuator/health`** — показывает полную информацию о состоянии системы и детальный статус подключения к БД H2 (`show-details=always`).
* **`/actuator/prometheus`** — генерирует системные метрики приложения в текстовом формате, оптимизированном для сборщика Prometheus.
* **`/actuator/loggers`** — позволяет просматривать и динамически изменять уровни логирования классов прямо на лету без перезапуска приложения.

### 🚀 В продакшн профиле (prod):
В целях безопасности доступ к инфраструктуре строго ограничен (`management.endpoints.web.exposure.include=health,info,prometheus`), а цепочка фильтров Spring Security разрешает сбор данных только для доверенных внутренних сервисов.
* Открыты только эндпоинты **`/actuator/health`**, **`/actuator/info`** и **`/actuator/prometheus`**.
* Отображение внутренней структуры и деталей подключения к PostgreSQL полностью скрыто (`show-details=never`) для предотвращения утечки данных об архитектуре сервера.
* Автоматический замер времени выполнения HTTP-запросов (HTTP Latency & RPS) включен по умолчанию средствами встроенного Micrometer.

### 📈 Инфраструктура мониторинга (Docker-окружение)
Полный стек мониторинга разворачивается автоматически в изолированной Docker-сети через `docker-compose.yml`:

1. **Prometheus (`port 9090`)** — каждые 15 секунд опрашивает эндпоинт приложения `/actuator/prometheus`, агрегирует и сохраняет метрики во временную базу данных (TSDB).
  * Веб-интерфейс: **http://localhost:9090** (Статус сборщика: *Status -> Targets*)
2. **Grafana (`port 3000`)** — визуализирует собранные данные Prometheus на интерактивных панелях. В систему интегрирован кастомный дашборд для мониторинга:
  * **JVM Memory (Heap/Non-Heap)** — загрузка и очистка памяти сборщиком мусора (GC).
  * **JVM Threads & CPU** — активность потоков и нагрузка на процессор в моменты пиковой работы.
  * **HTTP Requests (RPS)** — пропускная способность эндпоинтов бизнес-логики с фильтрацией по методам и HTTP-статусам ответов.
  * Веб-интерфейс: **http://localhost:3000** (Логин/Пароль по умолчанию: `admin` / `admin`). Данные и дашборды сохраняются между перезапусками контейнеров благодаря именованному volume `grafanadata`.

## 📝 Централизованное логирование (ELK Stack)
Для агрегации, структурированного анализа и быстрого поиска по логам всего приложения в production-профиле развернута классическая связка **Elasticsearch**, **Logstash** и **Kibana** (версия `8.12.2`).

### 🔄 Пайплайн доставки и обработки логов (File-based):
1. **Spring Boot App** записывает структурированные логи в файл `library-prod.log` внутри изолированного Docker-volume (`applogs`) с использованием строгого разделителя `|` для полей.
2. **Logstash** монтирует этот же volume, в реальном времени считывает новые строки, разбирает их с помощью плагина `dissect` на атомарные JSON-поля и отправляет в индексатор.
3. **Elasticsearch** индексирует входящие данные для мгновенного полнотекстового поиска.
4. **Kibana** предоставляет веб-интерфейс для глубокой аналитики.

### 📈 Инфраструктура ELK (Docker-окружение)
Все компоненты настроены в ресурсосберегающем режиме (`ES_JAVA_OPTS` / `LS_JAVA_OPTS`) специально для локальных сред разработки:

* **Elasticsearch (`port 9200`)** — база данных и поисковый движок.
  * Проверка статуса: **http://localhost:9200**
* **Logstash** — сервер конвейера обработки данных. Автоматически группирует логи по индексам `library-app-logs-YYYY.MM.dd`.
* **Kibana (`port 5601`)** — аналитическая визуальная панель.
  * Веб-интерфейс: **http://localhost:5601**
  * Для просмотра логов бизнес-логики перейдите в **Analytics -> Discover**, настройте Data View для индекса `library-app-logs-*` и используйте фильтр KQL (Kibana Query Language): `logger.keyword : c.k.l.*"`

## 🚀 Внедрение распределенного кэширования и аналитики (Redis)

  * **Счетчики в реальном времени:** При просмотре карточки книги через API, система автоматически инкрементирует её вес внутри структуры **Redis Sorted Set (ZSET)** за наносекунды.
  * **Декларативный кэш (Spring Cache):** Финальный сформированный список Топ-10 популярных книг защищен аннотацией `@Cacheable` с настроенным временем жизни (**TTL: 10 минут**).
  * **Реактивная инвалидация (@CacheEvict):** При добавлении, изменении или удалении книг администратором библиотеки, кэш рейтинга автоматически сбрасывается для предотвращения рассинхронизации данных.
  * **Отказоустойчивость и автономность:** Все вызовы обернуты в безопасные блоки обработки исключений, что гарантирует 100% работоспособность приложения и интеграционных тестов даже при временной недоступности сервера Redis.

## 🚀 Непрерывный анализ качества кода и безопасности (DevSecOps)

* **Глубокий аудит исходного кода (CodeQL):** При каждом пуше в репозиторий бесплатный движок автоматического анализа от GitHub сканирует Java-код на наличие скрытых багов, логических ошибок и уязвимостей.
* **Контроль сторонних зависимостей (OWASP):** Проект защищен от небезопасных внешних библиотек с помощью автоматического сопоставления твоего `pom.xml` с официальной базой данных уязвимостей (CVE).

### 📊 Как пользоваться и читать отчеты:

* **Локальный отчет по уязвимостям:** Запусти в терминале команду `mvn clean verify`. После сборки открой интерактивный дашборд `target/dependency-check-report/dependency-check-report.html` в любом браузере для просмотра критичности угроз по шкале CVSS.
* **Облачный отчет по качеству кода:** Перейди в верхнем меню своего репозитория на GitHub во вкладку **Security** -> **Code scanning alerts**. Там будет доступен развернутый интерактивный список всех багов, уязвимостей и подсказок по улучшению кода Java.
* **Просмотр алертов:** Перейди в верхнем меню своего репозитория на GitHub во вкладку **Security** -> **Dependabot alerts**.
* **Анализ угроз:** В этом разделе доступен полный список библиотек, требующих обновления, с подробным описанием уровня критичности уязвимости и готовыми рекомендациями по исправлению кода.

## 🚀 Быстрый запуск в Docker (Production Mode)

Для развертывания всего стека (Spring Boot + PostgreSQL 16 + автоматические миграции Liquibase) вам понадобится только установленный **Docker Desktop**.

1. **Настройте окружение:**
   Создайте файл `.env` в корневом каталоге проекта и заполните своими данными (шаблон):
   ```text
   DB_NAME=library_db
   DB_USER=postgres
   DB_PASSWORD=your_secure_password
   DB_PORT=5432
   APP_PORT=8080
   JWT_SECRET=your_ultra_long_random_secret_key_here
   JWT_EXPIRATION=36000000
   ```

2. **Запустите контейнеры:**
   Выполните команду в терминале:
   ```bash
   docker-compose up --build -d
   ```

3. **Проверьте статус:**
  * Приложение будет доступно по адресу: `http://localhost:8080`
  * Документация Swagger UI: `http://localhost:8080/swagger-ui.html`

## 🛠️ Экспорт данных и отчетность. Интеграция почтового сервиса.

### Реализованная архитектура и стек технологий модуля:
* **Архитектурный паттерн «Стратегия» (Strategy Pattern):** Логика генерации документов полностью изолирована через интерфейс `BookExportService` и динамическую фабрику `BookExportFactory`, что позволяет добавлять новые форматы (например, CSV) без изменения существующего кода контроллеров.
* **Интерактивный Web UI (Thymeleaf + JS):** На страницу просмотра книги добавлен адаптивный блок управления отчетностью. Текст и иконка кнопки динамически меняются без перезагрузки страницы («Сохранить» для локального скачивания файлов / «Отправить» при выборе отправки на Email с валидацией поля ввода).
* **Генерация Excel (XLSX):** Реализована на базе **Apache POI**. Документ формируется в виде аккуратной карточки книги с применением стилей оформления (жирные шрифты заголовков, цветовое выделение шапки, тонкие границы ячеек и автоматический перенос длинного текста описания).
* **Генерация PDF:** Реализована на базе **OpenPDF** с полной поддержкой кириллицы. Реализован механизм динамического поиска и ленивой загрузки системных TrueType шрифтов (`Arial` / `DejaVuSans`) для корректного рендеринга русского текста как на локальной машине разработчика, так и внутри изолированного Docker-контейнера.
* **Модуль Почты (Spring Boot Starter Mail):** Создан надежный сервис `EmailServiceImpl` на базе `JavaMailSender` для отправки писем с поддержкой вложений в формате Multipart. Проведена интеграция со спецификацией Jakarta Mail.
* **Безопасность (Spring Security):** Настройки `SecurityConfig` скорректированы с сохранением строгой политики защиты сессий (Stateless) — эндпоинт экспорта отчетов `/books/*/export` безопасно добавлен в исключения CSRF-фильтрации для корректной обработки POST-форм.
* **Многопрофильная конфигурация инфраструктуры:** Настройки почтового клиента гибко разделены по целевым окружениям (`dev` / `test` / `prod` / `containers`). В файл `.env` и `docker-compose.yml` вынесены переменные среды, защищающие учетные данные на продакшене. Локальное тестирование и отладка писем в докере развернуты через почтовую заглушку **Mailhog** с веб-интерфейсом.

## 📧 Настройка почтового сервиса (Spring Mail)

Модуль отправки уведомлений и отчетов по электронной почте полностью сконфигурирован через переменные окружения. Для работы системы в профиле `prod` или внутри Docker-контейнеров необходимо заполнить соответствующие параметры в файле `.env`.

### 1. Настройка для Google Gmail

Для отправки писем через Gmail нельзя использовать основной пароль от аккаунта Google. Вам необходимо сгенерировать **Пароль приложения**:
1. Перейдите в настройки безопасности аккаунта: [://google.com](https://://google.com).
2. Обязательно включите **Двухэтапную аутентификацию** (если она выключена).
3. В строке поиска настроек вверху введите **«Пароли приложений»** и перейдите в этот раздел.
4. Укажите название приложения (например, `Library System`) и нажмите **Создать**.
5. Скопируйте сгенерированный 16-значный код (вводите его в `.env` слитно, без пробелов).

Добавьте в ваш `.env` файл следующие настройки:
```env
# --- MAIL CONFIGURATION (GMAIL PRODUCTION) ---
# Указываем SMTP-сервер Google и порт TLS
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587

# Твой реальный почтовый адрес Gmail, с которого будут уходить письма
MAIL_USERNAME=your-email@gmail.com

# Твой 16-значный пароль приложения, скопированный из аккаунта Google (без пробелов!)
MAIL_PASSWORD=vbyujmkiloptxcde

# Обязательные параметры авторизации и шифрования TLS для Google
MAIL_SMTP_AUTH=true
MAIL_STARTTLS_ENABLE=true
```

### 2. Настройка для Яндекс.Почты

Если вы хотите осуществлять отправку через инфраструктуру Яндекса, алгоритм получения пароля аналогичен:
1. Перейдите на страницу [Яндекс ID -> Безопасность](https://yandex.ru).
2. Найдите блок **Пароли приложений** и создайте новый пароль с типом **«Почта»**.
3. Скопируйте полученный 16-значный код.

Добавьте в ваш `.env` файл следующие настройки:
```env
# --- MAIL CONFIGURATION (YANDEX PRODUCTION) ---
# Указываем SMTP-сервер Яндекса и защищенный порт SSL
MAIL_HOST=smtp.yandex.ru
MAIL_PORT=465

# Твой реальный почтовый адрес на Яндексе
MAIL_USERNAME=your-email@yandex.ru

# Твой 16-значный пароль приложения Яндекса
MAIL_PASSWORD=abcd-efgh-ijkl-mnop

# Обязательные параметры авторизации и шифрования SSL для Яндекса
MAIL_SMTP_AUTH=true
MAIL_STARTTLS_ENABLE=true
```

> ⚠️ **Важно для Docker-окружения:** После любого изменения файла `.env` обязательно примените настройки и перезапустите контейнеры в терминале командой:
> ```bash
> docker-compose down && docker-compose up --build
> ```
